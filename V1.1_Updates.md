# CyberGuard AI - V1.1 Prototype Roadmap (3-Month Plan)

This document outlines the strategic roadmap for the V1.1 prototype of CyberGuard AI, targeting the National Top 50 Hackathon Showcase. The requirements focus on enterprise-level on-device privacy, military-grade anti-tampering, and optimized AI performance.

---

## 1. Advanced Cryptography & Model Protection (The Vault)
Since the 150MB ONNX and VAD models sit on the user's local storage, they are vulnerable to extraction on rooted devices. To prevent intellectual property theft, v1.1 will implement the following:

*   **AES-GCM Encryption:** The models will be stored encrypted at rest using AES-GCM (Galois/Counter Mode). 
*   **Hardware-Backed Keystore:** The AES decryption key will not be hardcoded. It will be generated and secured within the **Android Keystore System** (hardware-backed Trusted Execution Environment), making it physically impossible to extract the key even if the device is rooted.
*   **SHA-256 Integrity Checks:** Upon decryption, the system will run a SHA-256 cryptographic hash check against the model bytes. If the hash does not match our signed baseline, the pipeline will refuse to boot, preventing attackers from substituting malicious poisoned weights.
*   **RAM-Only Decryption Strategy:** To avoid Out-Of-Memory (OOM) crashes, we will decrypt the model sequentially via an `InputStream` into a secure, no-backup internal cache directory (`/data/data/com.example/`), or utilize C++ memory-mapped buffers via the NDK to bypass the JVM heap entirely.

## 2. Anti-Reverse Engineering & Obfuscation (The Black Box)
While Android bytecode is easily decompiled, we will layer multiple obfuscation techniques to deter reverse-engineering.

*   **JVM Bytecode (R8/ProGuard):** We will enforce strict R8 obfuscation in `build.gradle.kts`. A customized `proguard-rules.pro` will be written to aggressively mangle class and method names while preserving the JNI hooks required by `sherpa-onnx`.
*   **Native Obfuscation (NDK):** Sensitive strings (like API endpoints, cryptography salts, or model paths) will be moved out of Kotlin and compiled into the native C++ layer. We will utilize compile-time string encryption within the NDK to hide these secrets from Hex editors and strings analysis tools.

## 3. Environmental Security (The Tripwire)
A compromised execution environment invalidates all software security. CyberGuard AI will implement environmental checks before the background service initializes.

*   **Local Root Detection:** The app will scan for common indicators of compromise:
    *   Presence of `su` binaries in `$PATH`
    *   `test-keys` in OS build tags
    *   Known root management apps (Magisk, SuperSU)
    *   Dangerous mount points (`/system` mounted as Read-Write)
*   **Play Integrity API (Optional/Future):** For maximum security, we can integrate Google's Play Integrity API to cryptographically verify the device hasn't been tampered with.

## 4. Hardware Profiling & Validation
To guarantee zero dropped frames and prevent CPU throttling across fragmented Android hardware, we will implement rigorous physical profiling.

*   **Macrobenchmark Module:** We will integrate `androidx.benchmark:benchmark-macro-junit4`. This allows us to generate `.perfetto-trace` files locally.
*   **Metrics Tracked:** 
    *   Startup latency (ensuring SOS bypass triggers in < 50ms)
    *   Jank frames during Active Call UI rendering
    *   Heap memory usage during the 150MB model load

---

## 5. AI Pipeline Fine-Tuning & Accuracy Optimization
With 3 months available, we will transcend off-the-shelf models and produce highly tailored inference files to maximize scam detection precision.

*   **Custom Fine-Tuning (Sherpa ONNX & Silero VAD):** We will fine-tune the existing models using custom datasets containing specific regional accents, background noise profiles (e.g., street noise, crowded rooms), and known scammer cadence patterns.
*   **Quantization:** After fine-tuning, the models will be re-quantized (INT8) to ensure the 150MB footprint does not increase, preserving our 17ms inference window.

## 6. Offline Threat Intelligence & Whitelist Databases
To ensure CyberGuard AI operates flawlessly at 0ms latency without an internet connection, we will bundle a pre-compiled threat database directly into the APK.

*   **Pre-Built CSV Datastores:** We will generate `.csv` (or pre-populated SQLite `.db`) files containing:
    *   **Global Emergency Contacts:** A comprehensive list of worldwide SOS numbers (911, 112, 100, 999) to guarantee the AI bypass logic never intercepts life-saving calls.
    *   **Telecommunication Threat Feeds:** A vast directory of known, verified scammer numbers (sourced from Telecommunication Department blacklists) loaded securely into the `BloomFilter` to instantly block known threats before the AI even needs to turn on.
