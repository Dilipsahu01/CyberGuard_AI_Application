## SLIDE 4: DEEP TECH — NLP Fine-Tuning & Multi-Modal Ensemble

### 4A: Layer-Wise Learning Rate Decay (LLRD) — Custom Transformer Surgery

**Why We Didn't Just Use an API:**

| Approach | Problem |
|:---|:---|
| OpenAI/Gemini API | Requires internet → fails offline. Latency 500ms+. Privacy violation. |
| Full MiniLM Fine-Tune | Catastrophic forgetting — destroys linguistic comprehension |
| **Our Approach: LLRD** | **Preserves language understanding + hyper-specializes for 5 scam intents** |

**Architecture of the Custom Model:**

| Layer | Training Strategy | Learning Rate | Purpose |
|:---|:---|:---:|:---|
| **Layers 1–3** |  **Frozen** | 0 | Preserve foundational linguistic comprehension |
| **Layers 4–6** |  Fine-tuned | **Low LR** | Adapt semantic representations to telecom fraud domain |
| **Layer 7 (NEW)** | 🔥 **Custom Head** | **High LR** | 5 neurons → 5 specific scam intent vectors |

**Input → Output:**
```
384-Dimensional MiniLM Embedding (22MB INT8 ONNX)
        │
        ▼
┌─────────────────────────────────────────┐
│  Custom Fully-Connected Layer 7         │
│  384 inputs → 5 output neurons          │
│                                         │
│  [Urgency] [Financial] [Coercion]       │
│  [Intimacy/Malware] [Trust]             │
└─────────────────────────────────────────┘
```

### 4B: Multi-Modal Ensemble Scoring (Defense in Depth)

**Why a Single AI Model Is Not Enough:**

| Signal Source | Type | What It Catches | Fallback Role |
|:---|:---|:---|:---|
| **IntentNLP (MiniLM)** | Probabilistic (ML) | Semantic coercion patterns | Primary detector |
| **RegexGate (19 patterns)** | Deterministic (Rules) | `\botp\b`, `digital.?arrest`, `\banydesk\b` | **Zero-compute thermal fallback** |
| **ArcTracker FSM** | Stateful (5-Phase) | Slow-burn grooming across multiple calls | Multi-session memory |
| **Bloom Filter** | Probabilistic (DS) | Known scammer hash lookup | O(1) instant flag |
| **ContactMemory** | Historical (DB) | Per-caller romance/intimacy score over days/weeks | Cross-session tracking |

**Ensemble Output:** Weighted, non-linear synergy fusion → **Single Risk Score (0–100)**

| Score Range | System Response |
|:---:|:---|
| **0–45** | Normal call, continue monitoring |
| **45–69** | Elevated — increased monitoring frequency |
| **≥70** | 🔴 **SCAM DETECTED** → Full-screen RED warning, device vibration, Guardian SMS sent |

**Non-Linear Synergy Example:**
```
Regex "OTP" detected (Score +12)     → alone: Score = 12 (safe)
NLP Urgency spike (Score +25)        → alone: Score = 25 (safe)
NLP Coercion spike (Score +20)       → alone: Score = 20 (safe)
                                        ─────────────────────
Combined + Synergy Amplification     → Score = 12 + 25 + 20 + 18 (synergy) = 75 → 🔴 SCAM
```

*Individual weak signals that are harmless alone become lethal when they co-occur. That is the synergy engine.*

**The 82-Bit Binary Telemetry Protocol (98% Bandwidth Reduction):**

| Field | Bits | Description |
|:---|:---:|:---|

| `TotalCalls` | 8 | Historical call count (0–255) |

| `Trust Intent` | 7 | NLP vector (0–100) |
| `Ensemble Risk Score` | 7 | Final composite (0–100) |

| Protocol | Payload Size | Transport |
|:---|:---:|:---|
| Standard JSON REST API | ~500 bytes | HTTP/HTTPS |
| **CyberGuard 82-bit Binary** | **10.25 bytes** | TCP + DSCP 0xB8 (URLLC request) |
| **Silent SMS Fallback** | **9 bytes** | Hex SMS (LoRa/low-bandwidth) |
| **Reduction** | **98%** | — |

**The Bloom Filter — Carrier-Scale Threat Distribution:**

| Parameter | Value |
|:---|:---|
| **Matrix Size** | 10,000,000 bits (**1.22 MB** uncompressed) |
| **Compressed Wire Size** | **300–400 KB** (gzip/zstd over HTTPS) |
| **Hash Functions** | MurmurHash3 (128-bit) + xxHash32 |
| **Optimization** | Kirsch-Mitzenmacher: $g_i(x) = h_1(x) + i \cdot h_2(x)$ |
| **Lookup Time** | **O(1) constant** (regardless of 1K or 1M entries) |
| **False Positive Rate** | **~0.00009%** (< 1 in 1,000,000) for 100K entries |
| **Scaling** | Filter size stays **fixed at 1.22 MB** from 1K to 1M+ threats |

| Security Layer | Implementation |
|:---|:---|

| **Key Storage** | Android Hardware Keystore (TEE / StrongBox) — non-exportable |

| **Integrity Check** | SHA-256 hash verification against signed baselines |
| **Cache Purge** | Decrypted models wiped from `noBackupFilesDir` after RAM load |

| **Database** | SQLCipher AES-256 encrypted Room DB |
| **Transport** | TLS 1.3 + Certificate Pinning |
| **Telemetry Auth** | HMAC-SHA256 (`X-App-Signature` header) |
| **PII Scrubbing** | OTPs → `[OTP]`, Account IDs → `[ACCOUNT_ID]`, Names → `[NAME]` |
